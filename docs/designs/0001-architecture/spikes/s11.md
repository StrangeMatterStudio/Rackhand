# Spike S11: collectors on current distributions

**Question (design 17, S11):** on systems that log only to the journal (no `/var/log/auth.log`), can a static probe
binary read SSH logins, invalid users and sudo events; and on a host where the ZFS ARC holds most of the memory, what
reading of available memory keeps the 7.6.1 memory rules from firing on a healthy host?

**Answer:** both reading methods return every event on Debian 12 and Ubuntu 24.04. On ZFS, `MemAvailable` leaves the
ARC out: count the ARC above its minimum (`size - c_min` from `arcstats`) as available.

## Method

Debian 12 and Ubuntu 24.04 containers ran systemd and OpenSSH with rsyslog removed and no `auth.log`. Into each:
three key logins as `u1`, one login attempt as an unknown user, and two logins that ran `sudo -n /usr/bin/true` (so
five accepted logins and two sudo commands). Two methods read the journal afterwards:
- `journalctl -o json` filtered to `sshd`, `sshd-session` and `sudo`, with a cursor file, as the probe would run it;
  a second read with the same cursor file checks that nothing is returned twice;
- a pure-Rust reader of the journal files.

For ZFS, the lab's Proxmox VE 9 node (4 GB, zfs 2.4.4, kernel 7.0.14-30-pve, `zfs_arc_max` at its default) wrote a
1.5 GB file to a ZFS pool and read it twice to fill the ARC; then `/proc/meminfo` and `arcstats` were read.

| Debian 12 | 252 | pure-Rust reader | 5 | 1 | 2 |

| Ubuntu 24.04 | 255 (255.4-1ubuntu8.18) | `journalctl -o json` | 5 | 1 | 2 |
| Ubuntu 24.04 | 255 | pure-Rust reader | 5 | 1 | 2 |

| ZFS reading (pve9, after filling the ARC) | Value |
| --- | --- |

## Consequences

- T22 reads authentication events with `journalctl -o json` and a cursor file where there's no auth log (it's on
  every systemd host and follows journal format changes); the pure-Rust reader is the fallback where `journalctl`
  is missing.
- T22 computes `mem.available_bytes` as `MemAvailable + max(0, size - c_min)` when `/proc/spl/kstat/zfs/arcstats`
  exists, and `mem.available_pct` from that. Without it, a ZFS host that has read 1.5 GB looks one heavy read away from
  the 10% warning. 7.4.2 says so.
- MV3 repeats the ZFS part on a real host's ARC under real load in L9.
