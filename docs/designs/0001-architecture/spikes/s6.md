# Spike S6: probe footprint

**Question (design 17, S6):** static musl binary size and steady RSS and CPU of a probe with iroh, aya and tokio,
against the 5.2 budgets: at most 15 MB on disk, 25 MB resident and 1% of a core.

**Answer:** all three variants are well inside the budgets. The probe uses a tokio **current-thread** runtime and iroh
with **only the `tls-ring` feature**; iroh's default features (metrics, portmapper) cost 0.7 MB and gain the probe
nothing, because probes dial their hub and never need a port mapping.

## Method

A probe skeleton was built with `opt-level = "z"`, LTO, one codegen unit, `panic = "abort"` and stripped symbols:
- an iroh 1.5 endpoint (relay disabled) connected to a listener running in another process;
- a trivial aya 0.16 tracepoint program on `sched/sched_process_exec`, loaded and attached;
- a tokio runtime;
- every 15 s, reads of `/proc/stat`, `meminfo`, `loadavg`, `net/dev`, `diskstats` and `uptime`, and a 1.2 KB payload
  sent zstd-compressed on a new QUIC stream.

The three x86_64 variants ran together as root for 30 minutes in the eBPF tier's VM (kernel 6.1.192, 2 vCPUs). RSS
(`VmRSS`) was sampled every 10 s; CPU is `utime + stime` over the run. Each listener counted the frames it received:
about 120 per variant, one every 15 s, so every probe ran the whole time. aarch64 was built with `cargo zigbuild`
(size only).

## Results

| Configuration | Static size | Steady RSS (max / mean) | Average CPU | Minutes |
| --- | --- | --- | --- | --- |
| x86_64 musl, current-thread tokio, iroh `tls-ring` only | 5.55 MB | 4.9 / 4.8 MB | 0.019% | 30 |
| x86_64 musl, multi-thread tokio (2 workers), iroh `tls-ring` only | 5.62 MB | 5.1 / 5.0 MB | 0.019% | 30 |
| x86_64 musl, current-thread tokio, iroh default features | 6.21 MB | 5.4 / 5.4 MB | 0.021% | 30 |
| aarch64 musl, current-thread tokio, iroh `tls-ring` only (size only) | 4.43 MB | - | - | - |

Budgets (5.2): 15 MB size, 25 MB RSS, 1% CPU. The skeleton leaves about 9 MB of binary size and 20 MB of RSS for the
collectors, buffer, helper client and the remaining eBPF programs.

## Consequences

- T22 and T42 use a current-thread tokio runtime and `iroh = { default-features = false, features = ["tls-ring"] }`
  in the probe. The hub may enable `portmapper` (S3: it helps hubs behind NAT go direct).
- T96's soak test keeps these budgets as its assertions.
