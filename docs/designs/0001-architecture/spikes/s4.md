# Spike S4: Proxmox privileges, firewall and upgrade command

**Question (design 17, S4):** which privileges does the Rackhand role need for snapshot, rollback, guest firewall,
conntrack flush, clone and power on Proxmox VE 8 and 9; what the datacenter firewall must be; whether a guest's rules
apply only when its network device's firewall flag is on, and whether saving and restoring the configuration is exact;
and which upgrade command Proxmox needs on its own hosts.

**Answer:** the 7.8.6 role works for every operation on both versions, and the quarantine round trip restores the
configuration exactly. Guest rules apply only with the datacenter firewall on and the device's `firewall=1`. Conntrack
**can't be flushed through the API**: that's the owner's decision before T72. Proxmox hosts upgrade with
`apt full-upgrade` (or `dist-upgrade`), never a plain `upgrade`.

## Method

On the lab's `pve8` (pve-manager 8.4.21, kernel 6.8.12) and `pve9` (9.2.31, kernel 7.0.14) nodes, a script created a
`@pve` user with the 7.8.6 role on `/` and an API token, then ran each operation through the API on the lab guests
`ct-test` (LXC 100) and `vm-test` (VM 200): with the whole role, then once with each privilege removed. Every operation
leaves the guests as it found them. The firewall round trip saved the container's firewall file and NIC line, applied a
quarantine-like set (policies DROP, DHCP out, the hub out), restored, and compared. A second run measured from the lab
hub whether a DROP policy stops pings to `ct-test` with the NIC flag off and on (datacenter firewall on with input
policy ACCEPT, so the node stayed reachable). The API schema shipped on the node (`apidoc.js`) was searched for
conntrack, and the admin guide shipped on the node for the upgrade command. The script's user, role and token were
deleted afterwards on both nodes.

## Results

| Operation (API) | PVE 8 | PVE 9 | Fails without |
| --- | --- | --- | --- |
| list guests, guest status | yes | yes | `VM.Audit` |
| storage status | yes | yes | either of `Datastore.Audit` or `Datastore.AllocateSpace` |
| node status, datacenter firewall options | yes | yes | `Sys.Audit` |
| LXC and VM snapshot, delete snapshot | yes | yes | `VM.Snapshot` |
| LXC rollback | yes | yes | either of `VM.Snapshot` or `VM.Snapshot.Rollback`; on PVE 9 also `VM.PowerMgmt` (a running container is stopped and started) |
| reboot | yes | yes | `VM.PowerMgmt` |
| guest firewall options and rules | yes | yes | `VM.Audit`, `VM.Config.Network` |
| NIC firewall flag | yes | yes | `VM.Config.Network`, `SDN.Use` |
| full clone to `tank`, delete with purge | yes | yes | `VM.Allocate`, `VM.Clone`, `Datastore.AllocateSpace`, `SDN.Use` |

- **Firewall round trip:** applying changed the configuration; restoring gave it back identical on both versions.
- **NIC flag:** with the guest firewall on and policy DROP, `ct-test` still answered pings while its NIC had
  `firewall=0`, and stopped once it had `firewall=1`; both versions. With the datacenter firewall off (the lab's
  default), guest rules don't apply at all.
- **Conntrack:** the API has no conntrack path; it appears only as firewall options (`conntrack_max`,
  `conntrack_allow_invalid`, `conntrack_helpers`, timeouts).
- **Upgrade command:** the admin guide on PVE 8 uses `apt full-upgrade` 6 times and `dist-upgrade` 7 times; on PVE 9
  `apt full-upgrade` 12 times, `apt upgrade` 6 (in other contexts) and `dist-upgrade` 4. Proxmox's own instructions
  for its hosts are a full upgrade.

## Consequences

- 7.8.6 keeps its 11 privileges. `VM.Snapshot.Rollback` and `Datastore.Audit` are covered by `VM.Snapshot` and
  `Datastore.AllocateSpace` today, but they name what Rackhand uses and cost nothing.
- Quarantine of a Proxmox guest (T72) checks the datacenter firewall (`pve_firewall_off` otherwise), saves the device
  flags with the rest, and sets `firewall=1` on each device while quarantined; restoring puts the saved flags back.
- **Owner decision before T72:** how to cut a quarantined guest's existing connections, since the API can't flush
  conntrack. Options: (a) run `conntrack -D` for the guest's addresses on the Proxmox host through the hypervisor's own
  managed enrollment (a wrapper command), (b) briefly set the guest's NIC `link_down=1` and back, which breaks
  established TCP sessions from the guest's side but leaves host entries to time out, or (c) rely on the DROP policy
  plus a rule ordering that drops established traffic, if the Proxmox firewall allows it.
- `patch-proxmox-host` (T60) runs `apt-get dist-upgrade` non-interactively, and the helper counts a Proxmox host's
  pending updates with a dist-upgrade simulation.
- MV4 repeats the privilege check on real nodes in L9.
